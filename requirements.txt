# --- Core face detection & recognition ---------------------------------------
# insightface generates the 512-dim embeddings behind every stored vector,
# centroid and classifier decision, so the version is pinned rather than floated.
#
# 0.7.3 -> 1.0.1 was verified safe against this database before upgrading:
#   * model_zoo/arcface_onnx.py and utils/face_align.py are byte-identical, and
#     buffalo_l is unchanged, so the embedding maths did not move.
#   * scrfd.py (detection) was refactored for multi-scale, which shifts landmarks
#     very slightly.  Measured over 120 faces re-embedded on GPU: mean cosine
#     similarity 0.9991 vs the stored vectors (worst 0.986) -- ~40x smaller than
#     the 0.60 distance veto, so no decision changes.  1.0.1 is deterministic
#     run-to-run (72/72 bit-identical), so that delta is real, not GPU noise.
# Re-verify with the same method before moving off 1.0.1.
insightface==1.0.1

# !! INSTALL TRAP !!  insightface depends on `onnxruntime` (CPU-only) and
# `opencv-python`, NOT the -gpu / -headless builds used here.  A plain
#     pip install -r requirements.txt
# therefore ALSO pulls those in, and they SHADOW the variants below --
# silently dropping CUDAExecutionProvider (scanning falls back to CPU) and
# replacing the headless cv2 build with the GUI one.  After installing, run:
#     pip uninstall -y onnxruntime opencv-python
#     pip install --force-reinstall --no-deps \
#         onnxruntime-gpu==1.26.0 opencv-python-headless==5.0.0.93
# (the force-reinstall is needed because uninstalling removes shared files)
# Or install from requirements.lock, which has the resolved, working set.
#
# GPU also needs cuDNN on the loader path -- see the CUDA section of README.md:
#     export LD_LIBRARY_PATH=".venv/lib/python3.14/site-packages/nvidia/cudnn/lib:$LD_LIBRARY_PATH"
#
# These two are the last packages not on their latest release, and the ceiling is
# the CUDA generation rather than caution on our part.  Checked 2026-10-22:
#
#   * 1.26 is the last onnxruntime-gpu built for CUDA 12 (nvidia-cuda-runtime-cu12
#     ~=12.0, nvidia-cudnn-cu12~=9.0).  Every release from 1.27 on requires the
#     CUDA 13 stack (nvidia-cuda-runtime~=13.0, nvidia-cudnn-cu13~=9.0).  We are
#     on cu12, so going past 1.26 is a cross-generation migration of the whole
#     CUDA stack, not a version bump.
#   * Python 3.14 is NOT a constraint.  Every release from 1.26.0 on ships a
#     cp314 manylinux x86_64 wheel.  An earlier version of this note (2026-07-28)
#     blamed a missing cp314 wheel and capped at <1.26, but 1.26.0 and 1.27.0
#     had cp314 wheels from release, and 1.28.0's was uploaded the next day.
#   * 1.25.1 -> 1.26.0 was verified on the GPU before upgrading: detection boxes
#     and embeddings for 120 stored faces were bit-identical across the two
#     versions, and each was bit-identical run-to-run.
#   * nvidia-cudnn-cu12 is capped for the same reason: it only matters as part of
#     that stack, and moving it alone risks a silent fall back to CPU.
#
# Revisit when moving to CUDA 13 deliberately.  Re-verify that `scan-faces.py`
# still logs "loaded on GPU" afterwards, and compare embeddings against the
# previous version the same way.
onnxruntime-gpu>=1.17.0,<1.27
nvidia-cudnn-cu12<9.24

# decoded AVIF pixels, resize(INTER_AREA) and JPEG encode were all bit-identical

# APIs used here and inside insightface are long-stable core functions.
opencv-python-headless>=5.0.0
